Fix pipelined JSON-RPC request ordering in this MCP-style stdio server (src/index.ts).

When initialize, tools/list, tools/call, run_command_safe, and shutdown are written
to stdin in one burst (without waiting for responses), all prior responses must be
emitted before the shutdown response exits the process. Currently shutdown can exit
while the async tool calls are still pending, dropping their responses.

Requirements:
- Implement a serialized request queue (or equivalent) so requests are processed
  strictly in arrival order, each fully written before the next begins, and shutdown
  only exits after every earlier response has been flushed.
- Add a node:test case in test/server.test.ts that writes all five requests in one
  burst without awaiting and asserts responses for ids 1 through 5 all arrive in order
  before the process exits.
- Run: npm run build, npm test, and the manual pipeline smoke. All must pass.
